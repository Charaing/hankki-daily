# 한끼

먹은 음식을 찾고, 먹은 만큼 남기는 한국어 식단 기록 앱입니다. 토스에서 영감을 받은 밝고 간결한 반응형 인터페이스로 만들었습니다. 토스와 관계없는 독립 서비스입니다.

**[앱 바로 열기](https://charaing.github.io/hankki-daily/)**

## 기능

- 날짜별 아침·점심·저녁·간식 기록, 수정, 삭제와 삭제 취소
- 국내 공개 음식·가공식품·원재료 **352,361건** 검색, 분류 필터와 초성 검색
- g 또는 mL 기준 계산, 소수 인분과 사용자 지정 1인분 기준량
- 하루 칼로리·탄수화물·단백질·지방, 주간 리포트와 물 기록
- 최근 음식, 즐겨찾기, 1인분 영양정보로 나만의 음식 등록·삭제·삭제 취소
- 기초대사량 추정값에 연동하는 칼로리 비교 기준, 직접 설정과 영양소·물 목표
- 기기 자동 저장, JSON 백업·복원, 다른 탭의 변경 반영
- 추가 해외 식품 검색: Open Food Facts (외부 서비스 연결 필요)
- 모바일·태블릿·데스크톱 화면, 키보드 조작과 동작 줄이기 설정 지원
- **[몸 관리 탭](https://charaing.github.io/hankki-daily/#body)**: 날짜별 체중·체지방률·허리둘레, 7/30/90일/전체 체중 그래프와 7일 평균
- 한국 성인 BMI 구간, Mifflin–St Jeor 휴식대사량으로 추정한 대사량, 활동계수 기반 하루 소비열량
- 유지·천천히 감량·천천히 증량 목표 예시, 목표 체중 진행과 식단 칼로리 목표 적용
- 걸음 수·운동 시간·근력 운동·수면 기록, 자동 및 직접 체크하는 하루 습관
- 페이지·카드·모달·숫자·그래프·프로그레스·버튼·북마크·습관 체크 모션, 앱 내 애니메이션 스위치
- 브라우저 북마크 아이콘, iPhone 홈 화면 아이콘, 192·512px 앱 아이콘과 저장 방법 안내
- 평일 학교 점심 839kcal·탄107g·단36g·지30g 자동 합산, 대한민국 공휴일·대체공휴일 제외, 방학·휴업일·당일 제외 설정
- 한 화면 작업 공간과 몸 관리·리포트 세부 탭, 긴 목록·대화만 패널 내부 스크롤

## 학교 점심

학교 점심은 기본적으로 2026-11-13부터 오늘까지의 평일에 839kcal·탄수화물107g·단백질36g·지방30g을 한 번 합산합니다. 사용자 제공 사진의 수치를 사용하며 탄단지는 추정 평균값입니다. 열량은 사진에 적힌 값을 그대로 사용하고 탄단지로 다시 환산해 덮어쓰지 않습니다. 가상 자동 기록으로 기존 수동 식단을 덮어쓰지 않으며, 설정만 백업하고 자동 기록은 조회 때 계산합니다. 실제 급식 중량은 알 수 없어 `null`입니다. 영양소는 설정에서 수정하거나 모르면 빈칸으로 비울 수 있습니다. 기존 950kcal 기본 설정은 새 평균값으로 자동 이전하면서 공휴일·방학·당일 제외·켜기 설정을 보존합니다. 별도로 바꾼 과거 열량은 유지합니다. 수동으로 점심 메뉴를 추가하면 자동 점심에 더해지므로, 실제 메뉴로 대체할 때는 자동 점심의 ×를 눌러 그 날짜를 제외하세요.

공휴일 자료는 [한국천문연구원 달력자료](https://astro.kasi.re.kr/kor/life/post/calendarData?year=2026)와 [우주항공청 2027년 월력요항](https://m.korea.kr/briefing/pressReleaseView.do?newsId=156768474)을 2026-11-13 확인한 2026·2027년 스냅샷입니다. 노동절·제헌절 공휴일 및 대체공휴일도 반영했습니다. 범위 밖 연도에는 확인 없이 자동 합산하지 않으며, 추가 임시 공휴일과 학교 자체 휴업·방학은 별도 설정이 필요합니다.



## 달력과 음식 종류

- **칼로리 달력**은 칼로리 숫자 없이 날짜의 색으로 표시합니다. 파랑은 목표 대비 적자, 빨강은 목표 초과, 초록은 목표 일치입니다. 선택 날짜의 식단 이름도 확인할 수 있습니다. 실제 소비열량 대비 적자를 뜻하지 않습니다.
- 미기록과 미래 날짜는 적자로 판정하지 않습니다. 학교 점심 자동 합산은 점으로 표시하며 일부 끼니만 기록한 날도 입력된 합계임을 안내합니다. 목표를 바꾸면 오늘부터 적용하고 이전 날짜 목표는 보존합니다. 기존 백업도 읽고 새 목표 이력은 백업에 포함합니다.
- 음식 검색과 보관함을 **직접 해먹기(요리·원재료)** / **완제품(국내 포장 제품·해외 제품)**으로 나눴습니다. 직접 등록 시 종류를 고를 수 있습니다.
- 이름·종류·제조사 기준으로 같은 음식은 검색 결과 한 줄로 묶습니다. 영양소·단위·1인분량까지 같은 중복은 하나만 보여 주며, 수치가 다른 기준은 상세 화면에서 선택합니다. g과 mL를 임의 변환하거나 다른 제조사의 영양정보를 섞지 않습니다. 원본 공개 DB 및 사용자가 실제로 남긴 식단 기록은 삭제하지 않습니다.
- AI 코치와 Google AI 호출 기능을 제거했습니다. 외부 연결은 사용자가 누르는 Open Food Facts 검색에만 필요합니다.

## 몸 관리 계산

BMI 구간은 [대한비만학회 성인 기준](https://general.kosso.or.kr/html/user/core/view/reaction/main/kosso/inc/data/guideline2022_vol8.pdf)을 사용합니다. 계산은 반올림 전 값으로 판정합니다. BMI는 건강 상태를 단독으로 진단하지 않습니다.

‘기초대사량 추정’ 카드는 엄밀히는 [Mifflin–St Jeor 휴식대사량 예측식](https://pubmed.ncbi.nlm.nih.gov/2305711/)의 결과입니다. `10 × 체중(kg) + 6.25 × 키(cm) − 5 × 나이 + 남성 5 / 여성 −161`로 계산합니다. 신체 정보는 성인 19세 이상을 받습니다. 활동계수 1.2 / 1.375 / 1.55 / 1.725 / 1.9와 유지 100% / 감량 90% / 증량 110%는 앱의 단순 계획 가정이며 실제 소비량·필요량·변화 속도를 보장하지 않습니다. 운동 기록은 활동량에 중복 가산하지 않습니다.

기본 칼로리 비교 기준은 기초대사량 추정값에 연동합니다. 신체 정보와 오늘까지의 최근 체중이 바뀌면 오늘부터 갱신하며 과거 날짜의 기준은 보존합니다. 정보가 없으면 기존 값은 임시 기준으로 표시하고 신체 정보 입력을 안내합니다. 기초대사량은 휴식 시 추정값이며 하루 권장 섭취량이 아닙니다. 하루 필요량에는 활동 등도 포함됩니다. [NIDDK 체중 계획](https://www.niddk.nih.gov/health-information/weight-management/body-weight-planner)을 참고하세요. 설정에서 직접 설정으로 전환할 수도 있습니다.

체중은 날짜당 한 개이며 같은 날 입력은 수정됩니다. 기존 기록의 날짜를 바꾸면 원래 날짜에서 이동합니다. 평균선은 해당 날짜를 포함한 최근 7일의 실제 측정값만 평균합니다. 과거 날짜 화면은 이후 날짜의 체중을 현재 수치로 쓰지 않습니다. 그래프 날짜 선택 슬라이더는 키보드로도 조작할 수 있습니다.

기존 version 1 식단 백업은 몸 관리 필드가 없어도 읽습니다. 새 백업에는 신체 프로필·체중·생활 기록·모션 설정도 포함하며 원본 식단을 유지합니다. 브라우저 저장소 키도 기존 `hankki.v1`을 유지합니다.

PDF 책자의 제2유형 라이선스와 구분합니다. 본 앱은 이 Excel DB를 가공하여 사용하며, 영양소 단위를 100g 또는 100mL 기준으로 통일하고 칼로리·탄단지·분류·제조사·제공량을 추출했습니다. 원본 값이 없는 영양소는 `null`을 유지합니다. 자료의 보증이나 공식 제휴를 뜻하지 않습니다.

검색용 자료는 `data/foods-*.json`에 분할하고 Web Worker에서 점진적으로 읽습니다. 최초 전체 검색에는 약 35MB의 데이터 다운로드가 필요합니다. 가능한 브라우저에서는 Cache API로 재사용합니다. 같은 이름이어도 제조사·조리법·분석 시료가 다를 수 있으며, 검색 중복 제거는 영양소·제공량·출처까지 동일한 경우에만 적용합니다.

해외 식품 검색은 [Open Food Facts](https://world.openfoodfacts.org/) API를 명시적으로 요청할 때만 사용합니다. 해당 데이터는 [ODbL](https://opendatacommons.org/licenses/odbl/1-0/) 라이선스를 따릅니다. 이 저장소에는 해당 데이터베이스를 복제하지 않습니다. 검색 결과는 사용자 제공 자료이며 원본 등록 상태에 따라 다를 수 있습니다.

## 계산 방식

`섭취 열량 = 100g당(또는 100mL당) 열량 × 섭취량 ÷ 100`

인분 입력은 `섭취량 = 인분 수 × 1인분 기준량`입니다. 검색·보관함·상세는 1인분의 무게와 영양정보를 표시합니다. DB 참고량이나 제품 포장 중량을 사용하며, 기준량이 없으면 임의로 100g을 1인분으로 정하지 않고 실제 무게 입력을 요청합니다. **포장 중량은 권장 1회 섭취량을 의미하지 않습니다.** 직접 등록도 1인분 무게와 해당 영양정보를 입력하며 내부 저장만 100g/100mL로 환산합니다. 단위 전환 시 양의 정밀도를 보존하고, 표시할 때만 반올림합니다. g과 mL는 임의 환산하지 않습니다. 누락 영양소는 0으로 단정하지 않으며 합계에 일부 정보만 반영되었다는 안내를 표시합니다.

영양정보는 제품·조리법·재료에 따라 차이가 있습니다. 신체 정보가 없는 새 기기의 2,000kcal는 BMR 연동 전 임시 비교 기준입니다. 식품 종류 전체를 빠짐없이 보장하지는 않으므로 목록에 없는 음식은 직접 등록할 수 있습니다. 보관함의 직접 등록 탭에서 삭제할 수 있으며, 삭제 직후 되돌리기를 제공합니다. 이미 남긴 식단의 영양정보는 별도 보관하여 유지합니다.

앱의 핀치·더블 탭 확대와 Ctrl/⌘ 확대 단축키·Ctrl 휠을 억제합니다. 브라우저 메뉴나 운영체제의 접근성 확대까지 제어하지는 않습니다.

## 기록 보관

계정·서버 DB·분석 추적 도구를 사용하지 않습니다. 식단은 해당 브라우저의 `localStorage`에 저장됩니다. 브라우저 데이터 삭제, 기기 교체, 시크릿 모드 종료 전에 설정에서 백업하세요. 백업 파일에는 개인 식단이 담기므로 본인이 보관해 주세요. 복원 시 현재 기록을 교체하기 전에 명확한 확인 화면을 표시합니다. 백업 입력의 날짜·수량·단위·기준량·영양소를 검증하고 출력 문자를 이스케이프합니다.

국내 목록 로딩은 이 사이트에만 요청합니다. 해외 식품 검색을 직접 누르면 검색어가 Open Food Facts에 전송됩니다.

## 로컬 실행

Node.js 20 이상에서 별도 의존성 설치 없이 실행할 수 있습니다.

```sh
npm start
# http://127.0.0.1:4173
npm test
```

정적 파일로 구성되어 별도 빌드가 필요하지 않습니다. 모든 기능은 API 키 없이 사용합니다. AI 코치는 제거되었으며 이전에 저장한 AI 연결 키도 앱 시작 시 삭제합니다. `file://`로 열면 모듈·Worker가 차단되므로 HTTP 서버를 사용하세요. GitHub Pages는 main 브랜치의 루트 디렉터리를 게시합니다.

검증 내역은 [docs/qa.md](docs/qa.md)에 기록합니다.
